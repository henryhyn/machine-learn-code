# P1 客户流失预测

《讲透经典机器学习》的配套项目 P1。用一份真实的电信客户数据，把书里 B 部分的工作流 (数据、预处理、评估、防泄漏) 和 C 部分的模型从头走一遍，最后按业务代价选阈值、解释模型、交付一个能给新客户打分的脚本。

- 数据：UCI Iranian Churn (CC BY 4.0)，3150 行，去掉 300 行完全重复后 2850 行，流失率 15.6%，说明见 [data/README.md](data/README.md)。
- 主指标：**平均精确率 AP (PR 曲线下面积)**。正类只占 15.6%，准确率和 ROC-AUC 都会显得过于乐观 (见书中 B3)。同时报告 ROC-AUC，以及默认阈值 0.5 下的召回率和 F1。
- 评估方式：固定的 75% / 25% 分层切分 (`random_state=42`)；训练集上 5 折分层交叉验证选模型，测试集每个里程碑只用一次。

## 运行

在仓库根目录：

```bash
uv run python projects/p1_churn/m1_baseline.py
uv run python projects/p1_churn/m2_pipeline.py
uv run python projects/p1_churn/m3_compare.py    # 含 40 组随机搜索，一两分钟
uv run python projects/p1_churn/m4_threshold.py
uv run python projects/p1_churn/m5_explain_deploy.py   # 同时把模型保存到 models/churn_model.joblib
uv run python projects/p1_churn/predict.py 新客户.csv 打分结果.csv   # 用保存的模型打分
```

每个脚本打印结果表，并写入 `results/<里程碑>.json`。

## 里程碑

| 里程碑 | 脚本 | 做什么 | 对应章节 |
| - | - | - | - |
| m1 基线 | `m1_baseline.py` | 去重；多数类基线；原始特征直接训练逻辑回归 | B3 模型评估、B5 数据泄漏、C2 逻辑回归 |
| m2 预处理 Pipeline | `m2_pipeline.py` | 按列的含义处理 (计数类取对数再标准化、二值列独热、丢掉冗余的 age)，整个关进 Pipeline | B2 数据探索与预处理、B5 数据泄漏与 Pipeline |
| m3 多模型对比与调参 | `m3_compare.py` | 同一套交叉验证对比逻辑回归、决策树、随机森林、HistGradientBoosting；随机搜索调参 | C5 决策树、C7 随机森林、C8 Boosting |
| m4 阈值与不平衡 | `m4_threshold.py` | 假设“挽留收益 = 10 倍电话成本”，对比默认阈值、理论阈值、class_weight、按利润交叉验证选阈值 | C9 分类实战问题、B3 模型评估 |
| m5 解释与上线 | `m5_explain_deploy.py`、`predict.py` | 置换重要性；整个模型 (预处理 + 模型 + 阈值) 存成一个 joblib 文件，打分脚本加载它 | C7 随机森林 (特征重要性)、B5 (Pipeline 上线) |

以下数字由上面的脚本生成 (scikit-learn 1.9.1)，与 `results/*.json` 一致。

| m2 | 逻辑回归 + 按列预处理 | 0.762 ± 0.033 | 0.796 | 0.935 | 0.598 | 0.680 |

### m4：按业务代价选阈值 (测试集 713 人，流失 112 人；利润 = 10 × 抓到的流失客户 − 联系人数)

| 决策方式 | 阈值 | 联系人数 | 抓到的流失客户 | 召回率 | 精确率 | 利润 |
| - | - | - | - | - | - | - |
| 谁都不联系 | — | 0 | 0 | 0.000 | 0.000 | 0 |
| 所有人都联系 | — | 713 | 112 | 1.000 | 0.157 | 407 |
| m3 模型 + 阈值 0.5 | 0.50 | 106 | 97 | 0.866 | 0.915 | 864 |
| m3 模型 + 理论阈值 0.1 | 0.10 | 130 | 102 | 0.911 | 0.785 | 890 |
| class_weight=balanced + 阈值 0.5 | 0.50 | 109 | 99 | 0.884 | 0.908 | 881 |
| 按利润调阈值 (交叉验证) | 0.03 | 151 | 106 | 0.946 | 0.702 | 909 |

m4 把 m3 随机搜索选出的参数四舍五入后写死在代码里，测试 AP 为 0.947 (m3 表中调参后模型为 0.946)。

### m5：置换重要性 (测试集上打乱该列后 AP 的下降，重复 20 次)

| 特征 | AP 下降 | 标准差 |
| - | - | - |
| complains | 0.224 | 0.032 |
| frequency_of_use | 0.154 | 0.022 |
| seconds_of_use | 0.138 | 0.019 |
| call_failure | 0.104 | 0.011 |
| subscription_length | 0.102 | 0.013 |
| status | 0.057 | 0.010 |
| age_group | 0.050 | 0.007 |
| distinct_called_numbers | 0.037 | 0.011 |
| frequency_of_sms | 0.020 | 0.005 |
| customer_value | 0.009 | 0.004 |
| charge_amount | 0.000 | 0.002 |
| age | 0.000 | 0.000 |
| tariff_plan | -0.002 | 0.000 |

几点观察：

- **基线**：什么都不学的 AP 就是正类比例 0.156，模型要和它比。
- **去重**：不去重时，测试集 788 行中有 113 行在训练集里有一模一样的副本，测试分数会混进“背答案”的成分。
- **m1 → m2**：逻辑回归在原始特征上 5000 步都不收敛；按列预处理后收敛，AP 小幅提升。线性模型的上限主要在模型本身。
- **m2 → m3**：树集成模型大幅领先 (AP 0.76 → 0.95)。几个特征上流失率呈跳变式差异 (有投诉的客户流失率 83%，没投诉的 10%；不活跃 47%，活跃 5%)，这类阈值效应正是树模型擅长的。
- **调参**：HistGradientBoosting 的默认参数已经很强，40 组随机搜索只把交叉验证 AP 从 0.948 提到 0.953，测试集上没有差别，收益在波动范围内。
- **召回率**：即使最好的模型，默认阈值 0.5 下也只抓到约 87% 的流失客户。
- **阈值**：按利润交叉验证选出的阈值是 0.03，比理论阈值 0.1 (= 成本 / 收益) 低得多，说明模型给流失客户的概率偏低；利润从 864 (阈值 0.5) 提到 909。class_weight="balanced" 几乎不改变 AP，只是挪动了决策点。
- **解释**：投诉、通话次数、通话时长、通话失败次数、订阅时长是模型最依赖的特征；资费类型、消费等级几乎没用上。置换重要性不说明方向，也不说明因果。
